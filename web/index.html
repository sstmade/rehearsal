01Intent

Physics can certify the wrong goal.

A simulator checks whether the goal holds. It can’t tell whether it’s the goal you meant. That part belongs to the language model, so we measured it.

Make some room on the desk.

The model moved the mug to the coaster, then stacked the book on the laptop.

Physics: successYou: a book and a phone on your laptop

Put the cup in the fridge.

There is no fridge. The plan had no way to say no, so “nothing moved” passed.

Physics: successYou: it should have said so

So Rehearsal shows what it assumed, and asks when it should.

Before anything runs, the model lists its assumptions for you to confirm. It may ask one question, or refuse with a reason, instead of guessing.

Before rehearsing

“Which book should I put in the bowl: the large hardcover, medium paperback, or small notebook?”

or, for an impossible request

“The robot can only suction-pick and transport and has no cutting tool.”

Muse Spark’s words, quoted from GoalBench.

On 30 instructions written blind, by someone who never saw our prompts or results

21/30handled right with the old prompt, which had no way to ask or say no
28/30with the intent step: it lists its assumptions, asks one question when the task is ambiguous, and refuses when it’s impossible. 95% interval: 79–98%

Blind hold-out: 30 cases in English and Chinese, run once with the prompts frozen, 3 repeats each on Muse Spark; “right” means the goal the person meant, or a question or refusal when that was the correct answer, in at least 2 of 3 repeats. n = 30 is small, so the interval is wide. On the 60 development cases the prompt was written against it scored 60/60, which we treat as an upper bound, not the headline. Source: docs/intent.md, docs/goalbench.md.

02Geometry

Don’t let a language model guess carry heights.

How high to lift a tin past a 48 cm lamp is geometry, not language. So the model states the goal, a search finds the motion, and physics checks every candidate.

86/100first plans from the language model failed in simulation, on five hard tables
100/100solved when the model states the goal and a plain search finds the motion: no revisions, about 9 s of search
80%of noisy held-out runs succeed once physics stress-tests the search’s plans, up from 52% for the first plan it finds

Simulation (MuJoCo), five hand-designed tables (desk_02, kitchen_01, lamp_01, storage_01, windowsill_01): one instruction per table, 20 independent Muse Spark runs each, so 100 runs of 5 distinct tasks. Robustness: held-out seeds with randomized friction, mass and position. The tables were built to be hard for a language model’s geometry guesses, not for a grid search, and the stress gate adds time (106–111 s per task on average), so it suits rehearsal before the robot moves, not a live loop. Sources: EVAL.md, Evaluation v3; docs/hybrid.md.

03Reality

Then we checked the physics against a real robot.

Six recorded episodes of a real Franka arm from the public DROID dataset. Rehearsal rebuilt each table from the first camera frame, replayed the recorded motion, and predicted what would happen. Then we compared it with what the camera filmed.

Real robotRehearsal

5/6success or failure called right, with no false successes. A gripper rule with no physics also gets 5/6.
2.5 cmmedian error in where 14 objects ended up. Guessing that nothing moves scores 1.3 cm: most objects never moved.
1miss, with a cause we can name: the wedged cup. A sanity check that found no contradiction, not proof.

!The honest miss

The real cup came up wedged on the closed fingers.

The gripper went inside the tapered cup and lifted it by wedging. Our gripper model has no wedge contact, and the twin’s cup was a plain cylinder, so in the replay the fingers landed on the rim and the cup fell off. Rehearsal said failure; the real arm succeeded. A false alarm, not a false success, and a cause we can name.

On success or failure, a rule with no twin (the fingers stopped short of closed, then the hand lifted) makes the same six calls, including the same miss. Always saying “failure” would also score 4 of 6 with no false successes, and assuming nothing moves predicts final positions better (median 1.3 cm vs 2.5 cm; 11/14 moved-or-not, the same as the replay). So on six episodes the replay ties trivial baselines; it is a sanity check, and the evidence that would separate them needs more episodes where objects move. Replay mode: the robot’s motion is given, so this tests the twin (perception, geometry, contact, gripper), not the planner. The predictor never reads DROID’s success label. Source: docs/real_robot.md. Robot footage: DROID (Khazatsky et al., RSS 2024), CC BY 4.0.

          Technical details value of re-observing each object, selection vs held-out runs

          Extra successes if only this object is re-observed

          A second look is modelled as a smaller position uncertainty (σ 1.2 cm → 0.4 cm) for that object. The object is chosen on one set of random runs (“selection”) and the gain is then measured on a fresh set (“held-out”), so the headline number isn't flattered by the choice.
